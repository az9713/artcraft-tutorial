## Gaps found (app or harness, and what was done)
1. **lightcraft (app):** every 8-bit encode — JPEG, PNG, WebP, AVIF, 8-bit TIFF — crashes with "Illegal instruction" (exit 132) on this CPU (no AVX-512). 16-bit TIFF works. Workaround: lightcraft delivers 16-bit TIFFs; photocraft encodes the web JPEGs. DNG export refuses non-raw photos ("DNG export needs a raw photo"), so there is no DNG archive.
2. **lightcraft (input):** the shoot is photocraft renders, not camera RAW. The raw-processing path is untested.
3. **photocraft (app, MCP):** `file.placeEmbedded` is disabled over MCP; the label was copied and pasted from an opened document instead.
4. **vectorcraft → effectcraft (app):** Bahnschrift exposes only "Regular" in effectcraft; the Bold wordmark is matched with a same-colour stroke (2.4 % of size).
5. **effectcraft Lottie (player):** lottie-web ignores Merge Paths. The web sting uses even-odd fills instead (verified in Chrome).
6. **filmcraft (app):** MP4 files are written with `moov` after `mdat` (no fast start) and no option was found to change it. Progressive playback needs a server with HTTP Range support. Platforms that re-encode on upload are not affected.
7. **filmcraft (input):** the first build used a temp score (sustained sine chords from effectcraft's Tone effect). The user rejected it as a monotone noise (2026-10-09). The spot now uses a 30 s instrumental jingle from ElevenLabs Music v2.5 (`filmcraft/music/lumen-jingle-30s.mp3` = take C of 3 in `filmcraft/music/takes/`, 900 credits each; flow `ckO0MhirZeulZW65EMCF`). The music is therefore not craft-made. The :15 uses the jingle's last 15 s.
8. **designcraft (app):** parent pages could not be edited headless; the footer is placed on each page.
9. **pdfcraft (app):** 4 accessibility rules still fail on the combined kit (tagged-pdf, tagged-content, tagged-annotations, tab-order); combining dropped the designcraft tags. The product sheet is 34 MB for 2 pages because page extraction kept full-size images.
10. **Harness:** Chrome ran with the window hidden (`visibilityState: hidden`), so it did not load `<video>` elements; video was verified by decoding frames in effectcraft instead of in the browser.
